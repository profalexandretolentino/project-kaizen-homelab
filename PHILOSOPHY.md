# English

## Purpose

This document defines how engineering is approached within Project Kaizen.

The project is not intended to reproduce isolated tutorials or temporary demonstrations. It is an engineering laboratory in which deliberate practice, experimentation, documentation and continuous improvement are used to build both infrastructure and reusable technical knowledge.

Knowledge acquired during the project is considered as valuable as the resulting infrastructure itself.

## Engineering Principles

### 1. Documentation is part of the product

Documentation is not separate from delivery. It preserves context, makes knowledge reusable and allows the project to evolve without depending exclusively on the memory of its original author.

### 2. Understanding is more important than memorization

Tools, languages and platforms change. Engineering work should prioritize understanding systems, concepts and trade-offs rather than memorizing isolated commands or procedures.

### 3. Every decision must have a reason

Engineering decisions should be based on a clear problem, context and expected result. Architecture should explain why something was built, not only how it was implemented.

### 4. Simplicity is preferred over unnecessary complexity

Complexity should be introduced only when it solves a real engineering problem. Clear and maintainable solutions are preferred to sophisticated solutions without proportional value.

### 5. Continuous improvement is a process

Project Kaizen evolves through small, deliberate improvements. Each Sprint should leave the project more organized, understandable, maintainable or reliable than it was before.

Small improvements accumulated over time create stronger systems.

### 6. Reproducibility is a design requirement

Engineering knowledge is incomplete when an environment or service depends on undocumented memory. Solutions should be designed so that another engineer can understand and recreate them from the repository.

### 7. Automation is preferable to repetition

Repeated manual work is a signal to evaluate automation. Automation should reduce avoidable effort, increase consistency and preserve reproducibility without adding unnecessary complexity.

### 8. Security is part of design

Security should be considered while systems, services and workflows are designed. It should not be treated as an isolated activity performed only after implementation.

### 9. Engineering decisions preserve context

Technical decisions form part of the project's knowledge. Their reasoning should remain available so that future changes can be understood in relation to the context in which earlier decisions were made.

### 10. Learning never reaches completion

Project Kaizen is intentionally designed to evolve. Technologies, practices and understanding will continue to change, making learning a permanent engineering activity rather than a final stage.

## Official Motto

> Everything built must be understandable, reproducible and maintainable.

# Português

## Propósito

Este documento define como a engenharia é conduzida dentro do Project Kaizen.

O projeto não existe para reproduzir tutoriais isolados ou demonstrações temporárias. Ele é um laboratório de engenharia no qual prática deliberada, experimentação, documentação e melhoria contínua são utilizadas para construir tanto infraestrutura quanto conhecimento técnico reutilizável.

O conhecimento adquirido durante o projeto é considerado tão valioso quanto a própria infraestrutura construída.

## Princípios de Engenharia

### 1. A documentação faz parte do produto

A documentação não está separada da entrega. Ela preserva contexto, torna o conhecimento reutilizável e permite que o projeto evolua sem depender exclusivamente da memória de seu autor original.

### 2. Entender é mais importante do que decorar

Ferramentas, linguagens e plataformas mudam. O trabalho de engenharia deve priorizar a compreensão de sistemas, conceitos e compensações em vez da memorização de comandos ou procedimentos isolados.

### 3. Toda decisão deve possuir uma justificativa

As decisões de engenharia devem partir de um problema, de um contexto e de um resultado esperado claramente definidos. A arquitetura deve explicar por que algo foi construído, e não apenas como foi implementado.

### 4. A simplicidade é preferível à complexidade desnecessária

A complexidade deve ser introduzida apenas quando resolver um problema real de engenharia. Soluções claras e sustentáveis são preferíveis a soluções sofisticadas sem valor proporcional.

### 5. A melhoria contínua é um processo

O Project Kaizen evolui por meio de melhorias pequenas e deliberadas. Cada Sprint deve deixar o projeto mais organizado, compreensível, sustentável ou confiável do que estava antes.

Pequenas melhorias acumuladas ao longo do tempo constroem sistemas mais fortes.

### 6. A reprodutibilidade é um requisito de projeto

O conhecimento de engenharia é incompleto quando um ambiente ou serviço depende de memória não documentada. As soluções devem ser projetadas para que outro engenheiro possa compreendê-las e recriá-las a partir do repositório.

### 7. A automação é preferível à repetição

O trabalho manual repetitivo é um sinal para avaliar a automação. A automação deve reduzir esforço evitável, aumentar a consistência e preservar a reprodutibilidade sem adicionar complexidade desnecessária.

### 8. A segurança faz parte do projeto

A segurança deve ser considerada durante o projeto de sistemas, serviços e fluxos de trabalho. Ela não deve ser tratada como uma atividade isolada executada somente após a implementação.

### 9. As decisões de engenharia preservam contexto

As decisões técnicas fazem parte do conhecimento do projeto. Suas justificativas devem permanecer disponíveis para que mudanças futuras sejam compreendidas em relação ao contexto no qual decisões anteriores foram tomadas.

### 10. O aprendizado nunca termina

O Project Kaizen foi projetado intencionalmente para evoluir. Tecnologias, práticas e entendimento continuarão mudando, tornando o aprendizado uma atividade permanente de engenharia, e não uma etapa final.

## Lema Oficial

> Tudo o que for construído deve ser compreensível, reproduzível e sustentável.
